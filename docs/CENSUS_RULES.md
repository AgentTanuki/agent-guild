# Agent Guild Discovery Census Rules

Status: pre-registered with Agent Guild 2.5.34, before the corresponding
distribution push. Rule version: `agent-guild/discovery-reach/v1`.

## Claim being measured

The target claim is deliberately narrow:

> At least 25,000 distinct attributable discovery actors under Census Rules
> v1 (T1: _n1_, T2: _n2_, T3: _n3_).

It is not a claim about 25,000 humans, minds, paying users, installations,
independent operators, or Sybil-resistant identities. Raw hits, directory
listings, repository clones, downloads, stars, third-party population claims,
and crawler fetches cannot satisfy the target.

## Unit of account

One actor is one durable, privacy-safe actor key already used by production
attribution. Authenticated calls resolve to a non-secret public account key.
Unauthenticated HTTP calls use a purpose-scoped hash of network address plus
User-Agent; A2A and MCP use their transport-specific privacy-safe bindings.
The same actor counts once across every event, surface, operation, and repeat
visit.

Unauthenticated distinctness is imperfect: shared egress can undercount and
rotating egress can overcount. That is why tiers are always published and T3
is explicitly Sybil-unresolvable.

## Qualification tiers

Tiers are exclusive; the strongest evidence wins.

1. `T1_key_proved_member`: a registered Guild member that completed the
   shipped key-possession proving rung and subsequently produced an event.
2. `T2_named_mcp_client`: a named third-party MCP client accepted by
   `attribution.is_genuine_external`; the client name must not appear in
   `OURS_MCP_CLIENTS`.
3. `T3_framework_ua_actor`: an external event whose User-Agent matches the
   pinned `FRAMEWORK_RE` and is accepted by `is_genuine_external`. This is a
   reach lower bound, not a Sybil-resistant identity count.

A bare authenticated but unproved member does not enter the census unless a
named MCP or recognised framework identity independently qualifies it.

## Permanent exclusions

The following never count:

- `AG_INTERNAL`, `AG_TEST`, `OPERATOR`, and `REGISTRY_CRAWLER` caller classes;
- every `GUILD_INTERNAL_ORIGINS` event;
- first-party authenticated traffic and bounded
  `KNOWN_FIRST_PARTY_INCIDENTS` corrections;
- UAs matching `TOOLING_UA_RE`, empty UAs, `mcp/remote`, and MCP clients in
  `OURS_MCP_CLIENTS`;
- UAs matching `CRAWLER_UA_RE`, including AI and registry crawlers;
- anonymous or explicitly unlinkable actors;
- randomised identities, Guild-operated fleets, reciprocal traffic rings, and
  any other traffic generated by Agent Guild to discover itself;
- repeated events from an already-counted actor.

These exclusions are implemented in `live/guild/app/attribution.py` and
`Store.discovery_reach`. The production attestation pins the exact deployment
commit in `proof.payload.rules_commit`; later code changes create a new proof,
not a silent rewrite of these rules.

## Evidence and replay

`GET /discovery/reach` returns the tiered count, coverage declaration, a
SHA-256 commitment to the sorted actor-evidence rows, and an Ed25519/JCS
signature from the Guild's persistent `did:key`.

`GET /discovery/reach/evidence` pages through the committed rows. Actor keys
are double-pseudonymised before publication. Pin the signed
`event_snapshot_rows` value by passing it as `snapshot_events` on every page;
this holds replay on one append-order snapshot while new events continue to
arrive. Concatenate every page in offset order, canonicalise the complete JSON
array with sorted keys and no whitespace, then SHA-256 it. The digest must
equal `actor_evidence_set_sha256`; the row and tier counts must equal the
signed payload. `scripts/verify_discovery_census.py` performs this replay and
verifies the signature.

The underlying event table is append-only in the production SQLite backend.
`measurement_history_complete: false` invalidates a milestone claim. The
evidence commitment can grow as new actors arrive; removing or reclassifying
historical rows changes the signed digest and is publicly detectable by anyone
who pins an earlier proof.

## Falsification and corrections

A reproducible misclassification is grounds for correction, not debate. Open a
public issue with the evidence and the implicated actor alias, rule, and proof
digest. A correction must ship as code plus a new signed proof; old signed
proofs remain verifiable and must not be deleted or described as current.
